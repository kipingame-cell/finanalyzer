# 💰 Финансовый анализатор

Продвинутое приложение для учёта личных финансов под Android. Ванильный стек (HTML/CSS/JS в Capacitor WebView) — никаких серверов, все данные только на устройстве.

## Возможности

- **Учёт доходов и расходов** — категории с иконками, цветами и месячными бюджетами
- **Автоматический импорт из уведомлений** — приложение читает уведомления банков (Сбер, Т-Банк, Альфа, ВТБ и др.) и предлагает записать операцию либо записывает её автоматически при включённой настройке: сумма, магазин, категория определяются автоматически
- **ИИ-советник** — работает и офлайн (анализ нормы сбережений, темпа трат, бюджетов, подписок, мелких покупок), а при вставке токена любого OpenAI-совместимого API (OpenAI / OpenRouter / Groq) даёт полноценный разбор финансов
- **Аналитика** — графики доходов/расходов за полгода, структура трат по категориям, топ мест трат
- **Автообновление** — приложение само проверяет GitHub Releases и предлагает скачать новую версию
- **Бэкап/восстановление** в JSON, демо-режим для показа

## Сборка APK (один раз)

1. Откройте репозиторий на GitHub → **Add file → Create new file**
2. Имя файла: `.github/workflows/build.yml`
3. Вставьте всё содержимое файла `build-apk.yml.txt` (без первых строк-комментариев можно оставить — это YAML-комментарии) → **Commit changes**
4. **Actions** → дождаться зелёного запуска → **Artifacts → app-debug-apk**

Каждый push в `main` собирает новый APK и публикует релиз `vX.Y.Z-bN` — установленные приложения сами увидят обновление. Чтобы выпустить обновление, поднимите `version` в `package.json` и в `APP_VERSION` в `www/js/config.js`.

### Постоянный ключ подписи (обязательно, один раз)

Без постоянного ключа каждая сборка подписывается случайным ключом, и Android не ставит новый APK поверх старого («приложение конфликтует с другим пакетом»). Настройка:

1. Откройте репозиторий → **Settings → Secrets and variables → Actions → New repository secret**
2. Имя: `KEYSTORE_BASE64`, значение: всё содержимое файла `KEYSTORE_BASE64.txt` (выдаётся разработчиком вместе с проектом) → **Add secret**
3. Обновите `.github/workflows/build.yml` свежим содержимым `build-apk.yml.txt` (карандаш → заменить всё → Commit)
4. **Последний переходной шаг:** старое приложение удалить (перед этим Ещё → Бэкап → скачать JSON), новый APK поставить начисто, бэкап восстановить. Дальше все обновления будут ставиться поверх, без удаления.

## Настройка на телефоне

1. Установить APK (разрешить установку из неизвестных источников)
2. **Android 13+: разблокировать ограниченные настройки.** Приложение установлено не из маркета, поэтому Android блокирует ему доступ к уведомлениям («Настройки с ограниченным доступом»). Снимается так: **Настройки телефона → Приложения → Финансовый анализатор → ⋮ (три точки сверху) → Разрешить ограниченные настройки** → подтвердить. Делается один раз.
3. Для автоимпорта трат: **Ещё → Операции из уведомлений → Открыть настройки доступа** → включить доступ к уведомлениям для FinAnalyzer
4. (Опционально) **Ещё → ИИ-токен** → вставить ключ OpenAI-совместимого API

> При обновлении на новую версию: установить свежий APK поверх старого (данные сохранятся). Приложение само предложит обновление, когда выйдет новый релиз.

## Структура

```
www/            веб-приложение (ванильный JS, без сборки)
  js/config.js  версия, репозиторий обновлений, категории, ключевые слова
  js/store.js   хранилище и статистика
  js/parser.js  парсер текстов уведомлений банков
  js/ai.js      офлайн-советы + облачный ИИ
  js/updater.js автообновление через GitHub Releases
  js/notify.js  мост к нативному слушателю уведомлений
native/         Java-модуль NotificationListenerService (подкладывается в android/ при сборке)
build-apk.yml.txt  workflow для Actions (переименовать в .github/workflows/build.yml)
```

## Импорт уведомлений в версии 1.2.0

В разделе **Ещё → Операции из уведомлений** включите **Автоматически записывать операции**.
По умолчанию настройка выключена: уведомления остаются предложениями для проверки.
Пока приложение открыто, очередь проверяется каждые 2 секунды; экран операций и аналитика обновляются после импорта.
Android-служба сохраняет уведомления при закрытом WebView, а операции из этой очереди записываются при возвращении в приложение.
Это не фоновая запись в финансовую базу: база находится в localStorage WebView.
В версии 1.2 очередь хранила последние 2000 уведомлений; с 1.3 используется SQLite без этого лимита.
Доступ к уведомлениям должен быть включён; ограничения батареи или принудительная остановка приложения могут мешать доставке.

Парсер требует явный признак операции и одну сумму операции в рублях.
Остаток, лимит, коды подтверждения, реклама и неуспешные платежи не импортируются.
Неоднозначные уведомления с несколькими суммами операции нужно внести вручную.
Поддерживаются обычный и расширенный текст, SMS MessagingStyle и резервный текст из InboxStyle.
Повторы одного уведомления отсеиваются по ключу Android и времени; одинаковые покупки в разное время остаются отдельными.
Уведомления банков не являются полной выпиской: отсутствующее уведомление нужно компенсировать ручным вводом.

### Проверка

`npm test` — регрессионные тесты парсера, категорий, дедупликации и автозаписи.
После установки APK: включите доступ, нажмите **Тест**, проверьте предложение покупки 450 ₽ и остаток 12 340,55 ₽.
Затем включите автозапись, повторите тест и убедитесь, что операция появилась один раз.
Проверьте реальную покупку при открытом приложении и ещё одну — при закрытом, с последующим открытием.
Кнопка **Тест** проверяет очередь, мост и парсер; получение реального уведомления системной службой проверяется отдельно.


## История SMS и фоновый сбор (1.3.0)

В разделе «Ещё → Операции из уведомлений» нажмите «Импортировать всю историю SMS»
и разрешите чтение SMS в системном диалоге. Импорт проходит все входящие SMS, которые
сейчас хранятся на устройстве, порциями по 250. В операции попадают только сообщения,
распознанные финансовым парсером; дата берётся из SMS. Повторный запуск безопасен.
Кнопка «Остановить импорт» завершает его после текущей порции; уже записанные операции остаются.
При ошибке можно запустить импорт снова. SMS не отправляются на сервер.
Удалённые сообщения, RCS и сообщения из чужих профилей Android недоступны.
READ_SMS — ограничиваемое Android разрешение: установщик/прошивка могут запретить выдачу;
приложение показывает эту ошибку и не требует назначения основным SMS-приложением.

Системная служба NotificationListenerService работает независимо от открытого экрана.
Очередь уведомлений теперь хранится в SQLite без прежнего лимита 2000; старая очередь
переносится автоматически. При переподключении службы проверяются ещё видимые уведомления.
После возврата в приложение сообщения распознаются, импортируются (при включённой автозаписи)
и удаляются из очереди только после обработки. Сама финансовая база по-прежнему в WebView:
закрытый экран не выполняет JS-парсер; фон обеспечивает сохранение исходных уведомлений.
В экране есть статус подключения и кнопка настроек фоновой работы. Разрешите автозапуск
и отключите ограничения батареи. Принудительная остановка или запрет со стороны прошивки
не обходятся; после них откройте приложение снова. Гарантии «никогда не будет остановлено» нет.


## Импорт выписки Яндекс Банка (1.4.0)

Ещё → Выписка Яндекс Банка. Получите в банке выписку по счёту с даты открытия
до нужного дня (если банк ограничивает период, импортируйте несколько файлов).
Выберите существующий счёт или создайте отдельный, загрузите PDF/CSV/TSV/TXT,
сверьте приход, расход, даты и количество строк и запишите выбранные операции.
PDF.js включён в APK: файлы обрабатываются локально, без передачи на сервер.

Текстовые PDF: даты ДД.ММ.ГГГГ и суммы в рублях со знаком либо явным описанием
операции. Сканы без текстового слоя и защищённые паролем PDF показывают ошибку.
CSV/TSV: Дата, Описание, Сумма (со знаком или типом операции), либо отдельные
колонки Приход/Расход. Дополнительно поддерживаются Валюта, Статус и ID.
CSV читается в UTF-8 или Windows-1251; кавычки и переносы в ячейках учитываются.
Excel нужно предварительно сохранить как CSV. Для дат без времени используется
12:00 по Москве. Неразобранные строки показываются отдельно, текст можно исправить.
Конкретный шаблон реальной выписки Яндекс Банка пока не проверен на пользовательском
файле. Нельзя считать импорт полным без сверки с исходной выпиской.

Повторный импорт тех же строк не добавляет их ещё раз. Совпадение с существующей
операцией по счёту, дню и сумме считается возможным повтором и снято с выбора:
пользователь может отметить его вручную. Одинаковые реальные строки внутри выписки
сохраняются раздельно. При изменении описаний в перекрывающихся выписках точное
распознавание повторов не гарантируется — проверьте отмеченные совпадения.
Банковский остаток по выписке не перезаписывается. Доходы/расходы, включая переводы,
используют существующую модель учёта приложения.

Проверка: npm install; GITHUB_RUN_NUMBER=52 npx cap sync android; npm test.
Зависимость PDF.js зафиксирована на 5.4.624, совместимой с Node 20 в сборке.
