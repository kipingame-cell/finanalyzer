## Замечания и порядок исправления

P0 — критический риск; P1 — высокая важность; P2 — существенное улучшение. Приоритеты — оценка аудита, не CVSS.

### FINANALYZER-01 · P2 · Обновлятор может предложить не-APK файл

- Статус: Подтверждено чтением кода.
- Место: `www/js/updater.js:28`; [открыть файл](https://github.com/kipingame-cell/finanalyzer/blob/main/www/js/updater.js). Номер строки относится к проверенному снимку.
- Проблема и последствия: Если релиз не содержит APK, fallback берёт первый asset, например SHA256SUMS.txt, и предлагает его как обновление.
- Исправление: Требовать APK подходящего пакета/канала; отсутствие установщика показывать отдельно.
- Критерий приёмки: Релиз только с txt/zip не даёт кнопки установки.

### FINANALYZER-02 · P2 · Зависимости сборки не зафиксированы lock-файлом

- Статус: Подтверждено деревом и package.json.
- Место: `package.json:15`; [открыть файл](https://github.com/kipingame-cell/finanalyzer/blob/main/package.json). Номер строки относится к проверенному снимку.
- Проблема и последствия: В проверенном дереве отсутствует lock-файл; несколько зависимостей заданы диапазоном ^. Повторная сборка одного commit может получить другой набор пакетов.
- Исправление: Закоммитить lock-файл и использовать npm ci в CI; обновления зависимостей оформлять явно.
- Критерий приёмки: Две чистые сборки используют одинаковые resolved versions.
